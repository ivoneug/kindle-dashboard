# Интеграция Codex

`dashd` теперь по умолчанию показывает Codex (`DASHD_AGENT=codex`). Рендер PNG,
HTTP API, навигация, Queue и shell-клиент на Kindle используются прежние.
Claude остаётся отдельным backend: `npm run start:claude`.

На тайлах и экране Usage провайдер определяет маскот: для Claude используются
прежние спрайты Clawd, для Codex — его монохромный SVG-значок. Значок сохранён
в `dashd/src/sprites/codex.svg` из ресурсов Codex.app (`codex_new`); установленное
приложение для его отрисовки не требуется.

## Источники данных

- Установленный `codex app-server --stdio`: только `thread/list`, `thread/read`
  и `account/rateLimits/read`. Адаптер не запускает модельные запросы, не
  возобновляет чаты и не подписывается на управление ими. Авторизацией занимается
  сам Codex; dashboard не читает `auth.json`.
- JSONL из `$CODEX_HOME/sessions`: текущее действие, последнее сообщение,
  `update_plan`, счётчики токенов и реальный `model_context_window`. Это внутренний
  формат Codex: неизвестные записи пропускаются. Читаются только добавленные
  байты, при первом запуске — последние 4 МБ каждого чата.
- Command hooks: точные события `SessionStart`, `UserPromptSubmit`, `PreToolUse`,
  `PostToolUse`, `Stop`, `Interrupt`, `SessionEnd`, `PermissionRequest`.
- Локальный IPC Codex Desktop (`$CODEX_HOME/ipc/ipc.sock`): по нажатию `C`
  находится владелец чата (`thread-owner-discovery`), dashboard подписывается
  на его состояние и передаёт `thread-follower-compact-thread`. Это отдельный
  канал от read-only app-server; dashboard не становится владельцем чата.

Отдельный app-server не знает runtime-состояния чатов в другом процессе
десктопного приложения (`notLoaded` у них относится к нашему процессу).
Поэтому состояние берётся из истории и хуков. Без свежих событий более
15 минут незавершённый исторический turn перестаёт считаться работающим.

Показываются корневые чаты за последние 24 часа, до 20. Архив и внутренние
Guardian/подагенты исключены. Импортированная история Claude показывается после
первого настоящего turn Codex. История не равнозначна списку открытых окон:
закончившийся чат остаётся IDLE до выхода из окна 24 часов.

## Установка хуков

```sh
cd dashd
npm run install-hooks:codex
```

Создаёт/обновляет `~/.codex/hooks.json`, сохраняет остальные обработчики и делает
резервную копию. Абсолютные пути к Node и `codex-hook.js` заключены в shell quotes.
Откат: `npm run uninstall-hooks:codex`.

После установки нужно просмотреть и доверить определения в Codex (`/hooks`).
Codex хранит доверие к текущему определению: установка файла сама по себе
не включает хук. Установщик не меняет доверие и не обходит проверку.
`/status` сообщает `hooks: true` только после реального вызова.

Node-обёртка получает JSON на stdin и пересылает нужные поля на
`http://127.0.0.1:8765/codex/hook`. Endpoint доступен только с loopback.
Обычные события ограничены 1,5 с, разрешение — 596 с при лимите runtime 600 с.

`PermissionRequest` обрабатывается на Kindle только для текущего turn с явно
указанным `approvals_reviewer: "user"`. Хук проверяет `session_id` и `turn_id`
по локальному transcript внутри `$CODEX_HOME/sessions` или `archived_sessions`.
Переключение разрешений посреди turn учитывается по более новому событию
`thread_settings_applied`, поэтому начинать новый turn для смены режима не нужно.
В режиме `auto_review` сразу возвращается `{}`: решение остаётся штатному
проверяющему Codex. Отсутствующий, устаревший или неизвестный контекст тоже
сразу передаётся Codex. Проверка выполняется и в обёртке, и в демоне;
глобальный `config.toml` для определения режима отдельного чата не используется.

## Названия чатов

Для имени на Kindle используется явное `thread.name` из Codex, затем
`session_index.jsonl`, затем `title` из `external_agent_session_imports.json`
для импортированных чатов. Превью первого сообщения и имя папки не подставляются
вместо названия. Изменения файлов названий подхватываются на следующем опросе.
Если название ещё не задано, показывается `Untitled session`.

## Ответы с Kindle

`Y` разрешает, `N` запрещает, `Back` передаёт запрос обычному интерфейсу Codex.
Деструктивные команды требуют второго `Y`; проверка показанного кадра сохраняется.
Без Kindle, при его отключении, по таймауту или если dashboard недоступен,
Codex получает отсутствие решения (`{}`). Это отличается от Claude:
`behavior: "ask"` Codex не возвращаем.

Хук может отвечать только на запросы, для которых Codex действительно вызывает
`PermissionRequest`. Встроенные ограничения runtime и политика доступа продолжают
применяться. Вопросы `request_user_input` показываются в Queue с вариантами и отмечают
сессию как ожидающую ответа; отвечать на них нужно в приложении. Центр на детальном экране поднимает приложение
Codex целиком (переход на конкретный чат пока не реализован).

Лимиты берутся из `account/rateLimits/read`; процент — использованная доля.
Если измерения нет, показывается недоступность. Число токенов контекста делится на
окно, сообщённое самим Codex, а не на таблицу предполагаемых размеров GPT.

## Compact с Kindle

`C` доступна в списке и деталях для Codex. ID выбранной сессии проверяется по
метаданным кадра, на котором нажата клавиша. Смена выбора после постановки
в очередь не меняет адресата. Queue, Usage и первое пробуждающее нажатие в
Ambient compact не запускают.

Перед отправкой команда ждёт `threadRuntimeStatus.type: idle` и пустой список
`requests` у живого владельца. `busy` и ожидающие ответа/разрешения чаты остаются
в очереди. Подтверждение IPC означает только приём запроса: `COMPACT DONE`
появляется после нового завершённого turn с `contextCompaction`.

Очередь и сведения об уже отправленных запросах атомарно сохраняются в
`dashd/.compact.json`. После рестарта неотправленные запросы продолжают ждать;
уже отправленные только наблюдаются. При потере подтверждения или владельца
после отправки показывается неопределённость, повторной отправки нет.

Это внутренний протокол приложения: используется версия 11 состояния и версия 1
команды compact. Неизвестная версия или разрыв последовательности patches
закрывает наблюдение; queued запрос переподключается, отправленный не дублируется.
Сокет должен принадлежать текущему пользователю и находиться в его защищённой
директории IPC. Отдельный app-server не используется для запуска compact.
Для чата без владельца нужно открыть его в Codex Desktop. CLI-only, cloud и
Claude не поддерживаются этой командой.
